BI Agent MVP: build it in verified steps

27 small milestones, from a Hello World API to a deployed natural-language BI agent. Each one is run, tested, committed, and approved before the next begins.

The loop every milestone follows

  1. Plan
  2. Implement
  3. Run
  4. Test
  5. Verify
  6. Save a Git checkpoint
  7. Wait for your approval, then extend

Test results are only reported as passed once you have shared the real output. Anything else is labelled "expected".

The text-to-SQL request path (milestones 15 to 17)

This is the part that needs the most care. The model proposes, deterministic code decides.

  1. Question arrives
  2. Resolve permitted tables and metrics
  3. LLM drafts SQL
  4. Parse and validate with SQLGlot
  5. Enforce role permissions
  6. Run read-only with limits
  7. Check the result
  8. LLM writes a grounded answer

Teal steps are deterministic code. Amber steps use the LLM. A rejected query stops at step 4 or 5 and never reaches the database.

Roadmap

Phase 0: Foundation

  1. M1Verify Python and Git; initialize the project
  2. M2FastAPI with /health and /hello
  3. M3pytest suite and first Git checkpoint

Gate: both endpoints respond correctly and tests pass.

Phase 1: Minimal application

  1. M4Minimal Streamlit page
  2. M5Frontend calls backend, with loading and error states
  3. M6Environment config, logging, correlation IDs

Gate: the UI shows the backend response; Streamlit calls the API only, with no database access.

Phase 2: LLM integration

  1. M7LLM service interface
  2. M8One working LLM request
  3. M9Failures, timeouts, cost limits

Gate: missing credentials, provider errors, and timeouts are handled.

Phase 3: Data access

  1. M10Local sample database and seed data
  2. M11Connectivity and deterministic queries
  3. M12Read-only execution and limits

Gate: a known aggregation matches the expected number; writes are refused.

Phase 4: BI foundations

  1. M13Minimal metric registry
  2. M14Schema and metadata retrieval
  3. M15First natural-language-to-SQL flow
  4. M16SQL parsing, validation, authorization
  5. M17Result validation, grounded answers

Gate: a golden question set passes, and unsafe SQL is rejected.

Phase 5: Conversational BI

  1. M18LangGraph, only if the working flow justifies it
  2. M19Conversation history and analytical state
  3. M20Follow-up questions and context
  4. M21Tables and basic charts

Gate: follow-ups resolve correctly; charts render from a structured spec, never model code.

Phase 6: Production readiness

  1. M22Authentication and RBAC
  2. M23Audit logging and monitoring
  3. M24Regression and evaluation dataset
  4. M25Docker packaging
  5. M26AWS deployment
  6. M27CI/CD, smoke tests, rollback

Gate: a deployed build passes smoke tests and can be rolled back.

Frontend decision: Streamlit replaces Next.js, so no Node.js is needed. It stays a thin client that calls the FastAPI backend over HTTP, which keeps it replaceable if you later need a custom UI or richer authentication.

Phase 7 (RAG, multiple sources, dashboards, root cause analysis, forecasting) waits until the core is reliable.

Rules that do not bend

  • One milestone at a time, then stop for approval.
  • Never extend a broken baseline.
  • Every capability gets tests; rerun earlier tests after each change.
  • No invented test results.
  • Add a dependency only when its milestone needs it.
  • No generated SQL runs without validation and database-level access controls.
  • The LLM never enforces authorization.
  • Secrets stay out of source code.
  • Diagnose from real error output before changing code.
  • Material architecture changes are explained and approved first.
