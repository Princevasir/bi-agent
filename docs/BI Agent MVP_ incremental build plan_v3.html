BI Agent MVP: build it in verified steps

27 small milestones, from a Hello World API to a deployed natural-language BI agent. Each one is run, tested, committed, and approved before the next begins.

The loop every milestone follows

  1. Plan
  2. Implement
  3. Run
  4. Test
  5. Verify
  6. Save a Git checkpoint
  7. Wait for your approval, then extend

Test results are only reported as passed once you have shared the real output. Anything else is labelled "expected".

How the architecture grows

Pick a stage. Highlighted boxes are new at that stage, faded dashed boxes do not exist yet.

Amber outline: calls an LLM. Teal highlight: added at this stage. Everything the LLM produces passes through deterministic code before it touches data.

The text-to-SQL request path (milestones 15 to 17)

This is the part that needs the most care. The model proposes, deterministic code decides.

  1. Question arrives
  2. Resolve permitted tables and metrics
  3. LLM drafts SQL
  4. Parse and validate with SQLGlot
  5. Enforce role permissions
  6. Run read-only with limits
  7. Check the result
  8. LLM writes a grounded answer

Teal steps are deterministic code. Amber steps use the LLM. A rejected query stops at step 4 or 5 and never reaches the database.

Rules that do not bend

  • One milestone at a time, then stop for approval.
  • Never extend a broken baseline.
  • Every capability gets tests; rerun earlier tests after each change.
  • No invented test results.
  • Add a dependency only when its milestone needs it.
  • No generated SQL runs without validation and database-level access controls.
  • The LLM never enforces authorization.
  • Secrets stay out of source code.
  • Diagnose from real error output before changing code.
  • Material architecture changes are explained and approved first.

import os

import requests

BACKEND_URL = os.getenv("BACKEND_URL", "http://localhost:8000")


class BackendError(Exception):
    """The backend is unreachable or returned an error."""


def get_json(path: str, timeout: float = 5.0) -> dict:
    try:
        r = requests.get(f"{BACKEND_URL}{path}", timeout=timeout)
        r.raise_for_status()
        return r.json()
    except requests.Timeout as e:
        raise BackendError("The backend took too long to respond.") from e
    except requests.ConnectionError as e:
        raise BackendError("Cannot reach the backend. Is it running?") from e
    except requests.HTTPError as e:
        raise BackendError(f"Backend returned status {r.status_code}.") from e
    except ValueError as e:
        raise BackendError("Backend returned invalid JSON.") from e

import logging
import os
import time
import uuid

from fastapi import FastAPI, Request

logging.basicConfig(
    level=os.getenv("LOG_LEVEL", "INFO"),
    format="%(asctime)s %(levelname)s %(message)s",
)
logger = logging.getLogger("bi_agent")

app = FastAPI(title="BI Agent API")


@app.middleware("http")
async def add_request_id(request: Request, call_next):
    request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())
    start = time.perf_counter()
    response = await call_next(request)
    response.headers["X-Request-ID"] = request_id
    ms = (time.perf_counter() - start) * 1000
    logger.info("request_id=%s %s %s -> %s %.1fms", request_id,
                request.method, request.url.path, response.status_code, ms)
    return response

Step-by-step guide: Phase 2, LLM integration

Decision: the app talks to the model only through a small LLMService interface. M7 builds it with a fake provider, so everything is testable with no credentials and no cost. M8 adds OpenRouter as the real provider, calling Qwen2.5 Coder 32B Instruct (slug qwen/qwen-2.5-coder-32b-instruct) through OpenRouter's OpenAI-compatible HTTP API. We call it with httpx directly instead of an SDK: one small dependency, and the timeouts are explicit. Nothing below is verified yet.

Before M8 you need: an OpenRouter account, a small credit balance, and an API key. When I checked, OpenRouter listed this model at about $0.66 per million input tokens and $1 per million output tokens, with roughly 33K tokens of context, hosted by a single provider. Prices and availability change, so confirm on the model page. With the 512 output-token cap used here, one maximum-size call costs roughly a tenth of a cent. A :free variant page also exists, but free variants are often rate-limited or withdrawn, so start with the paid slug. Keep the key only in your git-ignored .env. Prompts go to OpenRouter and the underlying provider, so check their data policy before you send real business data in later milestones.

backend/app/llm/openrouter.py:

import httpx

from app.llm.base import LLMError, LLMResult

OPENROUTER_URL = "https://openrouter.ai/api/v1/chat/completions"


class OpenRouterLLM:
    def __init__(self, api_key, model, max_tokens=512, client=None):
        self.model = model
        self.max_tokens = max_tokens
        self.client = client or httpx.Client(
            headers={"Authorization": f"Bearer {api_key}"}
        )

    def generate(self, prompt: str) -> LLMResult:
        payload = {
            "model": self.model,
            "messages": [{"role": "user", "content": prompt}],
            "max_tokens": self.max_tokens,
            "temperature": 0,
        }
        try:
            resp = self.client.post(OPENROUTER_URL, json=payload)
            resp.raise_for_status()
            data = resp.json()
            text = data["choices"][0]["message"]["content"]
        except (httpx.HTTPError, ValueError, KeyError, IndexError, TypeError) as e:
            raise LLMError("The model request failed.") from e
        usage = data.get("usage") or {}
        return LLMResult(
            text=text,
            input_tokens=usage.get("prompt_tokens", 0),
            output_tokens=usage.get("completion_tokens", 0),
        )

from threading import Lock

from app.llm.base import LLMRateLimitError


class TokenBudget:
    def __init__(self, limit: int) -> None:
        self.limit = limit
        self.used = 0
        self._lock = Lock()

    def check(self) -> None:
        with self._lock:
            if self.used >= self.limit:
                raise LLMRateLimitError("Token budget exhausted.")

    def record(self, tokens: int) -> None:
        with self._lock:
            self.used += tokens

Replace app/llm/openrouter.py in full:

import httpx

from app.llm.base import (
    LLMConfigError, LLMError, LLMRateLimitError, LLMResult, LLMTimeoutError,
)

OPENROUTER_URL = "https://openrouter.ai/api/v1/chat/completions"


class OpenRouterLLM:
    def __init__(self, api_key, model, max_tokens=512, timeout=20.0, client=None):
        self.model = model
        self.max_tokens = max_tokens
        self.client = client or httpx.Client(
            headers={"Authorization": f"Bearer {api_key}"},
            timeout=httpx.Timeout(timeout, connect=5.0),
        )

    def generate(self, prompt: str) -> LLMResult:
        payload = {
            "model": self.model,
            "messages": [{"role": "user", "content": prompt}],
            "max_tokens": self.max_tokens,
            "temperature": 0,
        }
        try:
            resp = self.client.post(OPENROUTER_URL, json=payload)
            resp.raise_for_status()
            data = resp.json()
        except httpx.TimeoutException as e:
            raise LLMTimeoutError("The model request timed out.") from e
        except httpx.HTTPStatusError as e:
            status = e.response.status_code
            if status == 408:
                raise LLMTimeoutError("The provider timed out.") from e
            if status == 429:
                raise LLMRateLimitError("The provider is rate-limiting requests.") from e
            if status in {400, 401, 402, 403, 404}:
                raise LLMConfigError(f"Provider rejected the request: HTTP {status}") from e
            raise LLMError(f"Provider error: HTTP {status}") from e
        except (httpx.HTTPError, ValueError) as e:
            raise LLMError("The model request failed.") from e
        if isinstance(data, dict) and "error" in data:
            raise LLMError("The provider returned an error response.")
        try:
            text = data["choices"][0]["message"]["content"]
        except (KeyError, IndexError, TypeError) as e:
            raise LLMError("Unexpected response shape from the model.") from e
        if not isinstance(text, str):
            raise LLMError("The model returned no text.")
        usage = data.get("usage") or {}
        return LLMResult(
            text=text,
            input_tokens=usage.get("prompt_tokens", 0),
            output_tokens=usage.get("completion_tokens", 0),
        )

There are no client-side retries here, so one slow call can take at most about the timeout you set. Add retries later only if you see transient failures, and remember they multiply latency.

import os
from datetime import date
from decimal import Decimal

import psycopg
from psycopg import errors


class DBError(Exception):
    """Database failure."""


class DBTimeoutError(DBError):
    """Query exceeded the time limit."""


def _json_safe(v):
    if isinstance(v, Decimal):
        return float(v)
    if isinstance(v, date):
        return v.isoformat()
    return v


def run_readonly(sql, params=None, max_rows=200, timeout_ms=5000):
    url = os.getenv("DATABASE_URL")
    if not url:
        raise DBError("DATABASE_URL is not set.")
    try:
        with psycopg.connect(
            url, connect_timeout=5,
            options=f"-c statement_timeout={timeout_ms} -c default_transaction_read_only=on",
        ) as conn:
            with conn.cursor() as cur:
                cur.execute(sql, params)
                if cur.description is None:
                    raise DBError("The statement returned no result set.")
                columns = [c.name for c in cur.description]
                rows = cur.fetchmany(max_rows + 1)
    except errors.QueryCanceled as e:
        raise DBTimeoutError("Query timed out.") from e
    except psycopg.Error as e:
        raise DBError("Database error.") from e
    truncated = len(rows) > max_rows
    return {
        "columns": columns,
        "rows": [[_json_safe(v) for v in r] for r in rows[:max_rows]],
        "truncated": truncated,
    }

Decimals become floats for JSON, which is fine for this sample but worth revisiting for real money values. When params is None, psycopg doesn't touch % characters, so LIKE '%x%' in generated SQL is safe to pass through.

from dataclasses import dataclass


class UnknownMetricError(ValueError):
    pass


@dataclass(frozen=True)
class Metric:
    name: str
    description: str
    expression: str
    base_where: str


@dataclass(frozen=True)
class Dimension:
    name: str
    select: str
    join: str = ""


METRICS = {
    "revenue": Metric("revenue", "Total amount of completed orders",
                      "SUM(o.amount)", "o.status = 'completed'"),
    "order_count": Metric("order_count", "Number of completed orders",
                          "COUNT(*)", "o.status = 'completed'"),
}
DIMENSIONS = {
    "region": Dimension("region", "r.name", "JOIN regions r ON r.id = o.region_id"),
    "month": Dimension("month", "to_char(date_trunc('month', o.order_date), 'YYYY-MM')"),
}


def build_metric_query(metric, dimension, start, end):
    if metric not in METRICS:
        raise UnknownMetricError(f"Unknown metric: {metric}")
    m = METRICS[metric]
    where = f"WHERE {m.base_where} AND o.order_date >= %s AND o.order_date < %s"
    if dimension is None:
        return f"SELECT {m.expression} AS value FROM orders o {where}", (start, end)
    if dimension not in DIMENSIONS:
        raise UnknownMetricError(f"Unknown dimension: {dimension}")
    d = DIMENSIONS[dimension]
    sql = (f"SELECT {d.select} AS dimension, {m.expression} AS value "
           f"FROM orders o {d.join} {where} GROUP BY 1 ORDER BY 1")
    return sql, (start, end)

import sqlglot
from sqlglot import exp
from sqlglot.errors import SqlglotError

from app.bi.schema import ALLOWED_TABLES

BLOCKED_PREFIXES = ("pg_", "lo_", "dblink", "set_config", "current_setting")


class SQLRejected(Exception):
    pass


def validate_sql(sql: str) -> str:
    try:
        statements = [s for s in sqlglot.parse(sql, read="postgres") if s is not None]
    except SqlglotError as e:
        raise SQLRejected("The SQL could not be parsed.") from e
    if len(statements) != 1:
        raise SQLRejected("Exactly one statement is allowed.")
    tree = statements[0]
    if not isinstance(tree, exp.Select):
        raise SQLRejected("Only SELECT statements are allowed.")
    if tree.find(exp.Into) or tree.args.get("locks"):
        raise SQLRejected("SELECT INTO and locking clauses are not allowed.")
    ctes = {c.alias for c in tree.find_all(exp.CTE)}
    for t in tree.find_all(exp.Table):
        if t.name in ctes and not t.db:
            continue
        if t.db or t.catalog:
            raise SQLRejected("Schema-qualified tables are not allowed.")
        if t.name.lower() not in ALLOWED_TABLES:
            raise SQLRejected(f"Table not permitted: {t.name}")
    for f in tree.find_all(exp.Anonymous):
        if f.name.lower().startswith(BLOCKED_PREFIXES):
            raise SQLRejected(f"Function not permitted: {f.name}")
    return tree.sql(dialect="postgres")

It returns the SQL re-serialized from the validated tree, so what you execute is what you checked. It rejects UNION on purpose, to keep the rules simple. The function denylist is incomplete by nature. That is why the database role, read-only transaction, timeout, and row cap from M10 to M12 remain the real enforcement. This validator is defense in depth.

import re

NUM = re.compile(r"\d[\d,]*\.?\d*")


def _numbers(text):
    out = set()
    for m in NUM.findall(text):
        try:
            out.add(round(float(m.replace(",", "").rstrip(".")), 2))
        except ValueError:
            pass
    return out


def is_grounded(answer, question, rows):
    allowed = _numbers(question)
    for row in rows:
        for v in row:
            if isinstance(v, (int, float)):
                allowed.add(round(float(v), 2))
    return _numbers(answer) <= allowed


def fallback_answer(columns, rows):
    if not rows:
        return "The query returned no rows."
    return "; ".join(", ".join(f"{c}: {v}" for c, v in zip(columns, r)) for r in rows[:10])


def answer_prompt(question, sql, result):
    return (
        "Answer the question in one or two sentences using ONLY the data below. "
        "Do not use any number that is not in the data.\n\n"
        f"Question: {question}\nSQL: {sql}\nColumns: {result['columns']}\n"
        f"Rows: {result['rows'][:50]}\nTruncated: {result['truncated']}"
    )

Update answer_question in service.py to run the guarded query, return the fallback without calling the LLM when there are no rows, otherwise draft an answer with generate(answer_prompt(...)), and use it only if is_grounded is true. The response gains answer and answer_source ("llm" or "fallback").

The check is deliberately strict. A date such as "2026-09" or a percentage the model computed will fail it and trigger the plain fallback. That costs polish, not correctness.

Tests (scripted LLM): an answer using only result numbers is accepted (source llm); an answer with an invented number falls back (source fallback); an empty result never calls the LLM (script it to raise if called); 1,380.00 and 1380 compare equal; truncated is passed through to the response.
